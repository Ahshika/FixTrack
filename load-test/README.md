# اختبار الضغط على سيرفر FixTrack

بيشغّل نسخة منفصلة من السيرفر على فولدر مؤقت (عمره ما بيلمس بيانات محل حقيقي)، وبيضغط عليها بـ [k6](https://k6.io)، والنتايج بتتعرض في Grafana.

## الملفات
- `fixtrack_load.js` — أوردرات صيانة بس: من 500 لحد 10000 أوردر في الدقيقة خلال 5 دقايق.
- `fixtrack_full.js` — كل أجزاء البرنامج مع بعض (بيع، آجل، مرتجع، صيانة كاملة، موافقة، محافظ، مصروفات، مستعمل، موردين، IMEI، مخزن) + 15 شاشة بتتفتح طول الوقت + باك أب في النص.
- `bench.js` — قياس أقصى سرعة: 30 جهاز بيبعتوا ورا بعض لمدة 40 ثانية.
- `server/load_server.dart` — السيرفر لوحده من غير الواجهة.
- `sampler.ps1` — بيسجل المعالج والذاكرة وحجم قاعدة البيانات كل ثانيتين.
- `make_dashboard.py` — بيحوّل النتايج للوحة Grafana (مصدر TestData).
- `تقرير-*.html` — تقارير k6 الكاملة.

## التشغيل
```bash
cd source
mkdir bin_load && cp ../load-test/server/load_server.dart bin_load/
dart build cli -t bin_load/load_server.dart -o ../load-test/srv
../load-test/srv/bundle/bin/load_server.exe <فولدر مؤقت فاضي> 18790
```
وبعدين من فولدر `load-test`:
```bash
k6 run --summary-export=summary.json --out csv=results.csv fixtrack_full.js
python make_dashboard.py . <uid مصدر TestData في Grafana> full
```

## النتايج (7 أكتوبر 2026)

| | قبل التصليح | بعد التصليح |
|---|---|---|
| أقصى سرعة (30 جهاز ورا بعض، `bench.js`) | 188 عملية/ثانية | 315 عملية/ثانية |
| عمليات فشلت في الاختبار الشامل | 1052 | 43 |
| تسجيل مصروف (الاستخدام العادي) | حوالي 6 ثواني | 6 أجزاء من الألف من الثانية |
| بيانات راحت من السيرفر للأجهزة | 1.2 جيجا | 96 ميجا |
| أعلى استهلاك ذاكرة | 540 ميجا | 136 ميجا |

اللي اتصلح:
1. شاشة الدرج بتجيب آخر 200 حركة بس (الإجماليات لسه محسوبة من كل الحركات)، وتسجيل المصروف مابقاش يرجّع الوردية كلها.
2. آخر ظهور للجهاز بيتسجل مرة كل دقيقة بدل مع كل طلب.
3. أوامر قاعدة البيانات بتتجهز مرة واحدة وتتحفظ.
4. طابور الاتصالات بقى 1024 بدل الافتراضي.

اللي لسه موجود: السيرفر بيشتغل على نواة واحدة، فبيوصل لآخره عند حوالي 7000 عملية في الدقيقة، والـ 43 اللي فشلوا اتقفل عليهم الاتصال لما كان فيه حوالي 800 اتصال في نفس اللحظة. الاتنين بعيد جداً عن شغل أي محل.
